# LDA 任务卡骨架

拷贝本目录开新卡,每张卡自成 git 仓库,由 LDA 的 autoresearch 循环(`./lda run`)驱动 agent 在卡上迭代。

## 结构

```
<卡名>/
├── .auto/
│   ├── prompt.md        # 任务书 + 审查反馈(只增不删)
│   ├── measure.sh       # 输出唯一进度指标 METRIC gates_passed=N
│   ├── checks.sh        # 防作弊:核验每个"通过"的证据文件
│   ├── config.json      # {"maxIterations": N}
│   └── state/GATES.tsv  # 检查点清单(tab 分隔)
└── evidence/            # 证据文件(每个通过的检查点挂一份)
```

## 生命周期

开卡(检查点先定死)→ 优化 agent 执行(每步 git 提交;micro benchmark 作即时反馈)
→ 每过一个检查点:写证据文件 + 更新 GATES.tsv → 检查 agent 对抗验证
(确认 / 打回 / 造假清零)→ End-to-End 验证 → 收尾(checks.sh 全绿 + 无残留文件复核)。

## 六条硬规矩

- "通过"必须挂自含五要素的证据:①命令 ②原始输出关键行 ③作业编号或产物路径 ④为什么支撑结论 ⑤作业最终状态与退出码(没有调度作业的门显式标 `NO-JOB`);
- 每个检查启用前,先对一个故意做坏的样本证明它会报错;
- 兼容边界(流程文档 §3 的八条线)任何一条被破坏,一票否决,不论提速多少;
- **checks.sh 的门号映射是本卡的配置**:开卡时逐门核对(从别的卡拷来的映射会检不存在的门、漏检真实的门);
- **收尾必须运行 checks.sh 并把退出码写进证据**——没跑过的防作弊检查等于没有;
- 预注册判据写成可执行断言放一处,脚本回读校验,文本与实现不一致即失败。
