# micro benchmark 的做法

**先注册后测量**:重复次数、方向、阈值先写进 `.auto/rules.json` 并 git 提交,再跑第一次数据。

- **同实例内 A,B,A,B 交替**:不交替会凭空造出约 5% 的"先跑者更慢";
- **三段 A→B→A′**:回测的 A′ 与 A 的差就是漂移,效应必须数倍于它;
- **两臂同仪器**:同一个入口脚本、同一组参数、同一个沙箱规格;不许只在一臂上加 flag;
- **单次负载 ≥10 秒**才配声称 1% 量级的结论(0.4 秒的负载只能分辨约 9.5%);重复次数先算后跑;
- **禁区**:文件同步类等待(fsync/sync_file_range)在沙箱的分层文件系统上近乎免费,
  这类测量必须去受控真机,不能在沙箱里定量;
- **测量有效性自证**:往对照臂注入一个已知的慢(如 `sleep 0.2`),必须被判显著慢;
  空对照(两臂完全相同)必须无显著差——两项都要留证据;
- **原始逐次观测入 `evidence/`**,不许只留汇总;数字带机器标识与日期。
